StriveNest ERP — Run Commands
==============================

PREREQUISITE (do this first, every time):
  MongoDB must be running locally before you start the backend.
  - Windows: start the "MongoDB" service, or run `mongod` in its own terminal.
  - Verify it's up on mongodb://localhost:27017 before continuing.

If MongoDB is NOT running, the backend will now fail immediately on startup
with a clear "[STARTUP ERROR] Could not reach MongoDB..." message in the
terminal, instead of hanging silently (this was patched — see
FIXES_APPLIED.md).


1) BACKEND
----------
cd backend
.\venv\Scripts\Activate.ps1        (or: python -m venv venv   then activate, if venv doesn't exist yet)
pip install -r requirements.txt
python seed_superadmin.py
python seed_subadmin.py
python seed_demo_employee.py
python -m uvicorn server:app --host 0.0.0.0 --port 8001 --reload

Verify before moving on:
  http://localhost:8001/docs        -> Swagger UI loads
  http://localhost:8001/api/health  -> {"status":"ok","database":"connected"}

  If "database" says "disconnected", MongoDB isn't reachable — fix that
  before testing the frontend.

6) DEPLOYING THE BACKEND TO RENDER (or any production host)
-------------------------------------------------------------
Required Render environment variables for the backend service:

  ENVIRONMENT=production
  DEMO_MODE=false
  MONGO_URL=<your production MongoDB connection string>
  DB_NAME=<your production database name>
  JWT_SECRET=<a real, private secret -- NOT "change_this_secret">
  SEED_SUPERADMIN_EMAIL=<a real admin email you control>
  SEED_SUPERADMIN_PASSWORD=<a strong, private password -- NOT SuperAdmin@123>

SEED_SUPERADMIN_EMAIL and SEED_SUPERADMIN_PASSWORD are REQUIRED in
production. If either is missing, the backend now refuses to start (see
config.py / FIXES_APPLIED.md) instead of silently seeding the SuperAdmin
account with the publicly documented default password "SuperAdmin@123".
This is what makes automatic SuperAdmin seeding on every startup (the fix
for the original production 401 issue) safe to leave on in production.

Recommended, not currently enforced by the app -- see FIXES_APPLIED.md:
  SEED_SUBADMIN_PASSWORD=<a private password, not "Subadmin@12">
  SEED_EMPLOYEE_PASSWORD=<a private password, not "Employee@123">
These two demo accounts are still seeded automatically even with
DEMO_MODE=false, using their documented default passwords if you don't
override them. They are lower-risk than SuperAdmin (SubAdmin/Employee, not
a full admin identity) but the same "known default password" issue applies
if you leave them unset in a real production deployment.


TROUBLESHOOTING "CORS error" IN DEVTOOLS
------------------------------------------
1. Confirm http://localhost:8001/api/health returns "database":"connected".
   If the backend never started (e.g. MongoDB down), every request —
   including the browser's CORS preflight — gets no response at all, and
   Chrome shows that as a "CORS error" with 0 bytes transferred, even
   though nothing is actually misconfigured.
2. Confirm the frontend really is on port 3000 (SuperAdmin), 3001
   (SubAdmin), or 3002 (Employee). The vite.config.js files now use
   strictPort: true, so if the port is already taken by something else,
   `npm run dev` will fail loudly instead of silently moving to a
   different port that the backend's CORS_ORIGINS doesn't allow.
3. Hard-reload the browser (DevTools > Network > Disable cache, then
   reload) after any .env or vite.config.js change — Vite does not
   hot-reload environment variables.
